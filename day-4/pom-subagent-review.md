# POM Independent Review
Date: 2026-09-29
Scope: 4 Page Objects (`src/pages/`), 1 helper (`src/helpers/bondCreation.ts`), 2 fixtures (`src/fixtures/qa.ts`, `src/fixtures/loginCases.ts`), 2 API clients (`src/api/`), 6 test-data files (`constants.ts`, `bondCreationData.ts`, `loginData.ts`, `loginCases.ts`, `bondCreationCases.ts`, `highValueCases.ts`), 14 specs under `tests/`. For context it also read `src/global-setup.ts`, `src/utils/environment.ts`, `playwright.config.ts`, `playwright.lockout.config.ts`, and `.github/workflows/playwright.yml`.

## Summary
The framework is in good shape. Test IDs are mapped in one typed place, and there is no `waitForTimeout`, no `.skip`/`.fixme`, no XPath, and no `.nth()` in `src/`, `tests/`, or `test-data/`. Missing data or accounts fail with clear messages. The main weakness is that several checks can pass while the feature is broken. The biggest is `LoginPage.assertRejected()`, which nine Login cases rely on and which is true the moment Sign In is clicked. Others check only the HTTP status of create-bond calls, or check an HTML-injection case that the page can never render. There is also a likely password leak through CI traces. Findings: **5 High, 8 Medium, 9 Low**, plus 6 unconfirmed items.

## Unconfirmed
- **BondCreationPage.ts:106**: `getByText(label).locator('..')`. If the parent element holds the whole header row, `toContainText(value)` in TC-024 could pass using a neighbouring label's value. To confirm, inspect the header DOM on the quote page.
- **LoginPage.ts:26-27**: `getByLabel(loginLabels.password)` is non-exact. If the page has a show-password toggle with an aria-label such as "Show password" (the comment at usability.spec.ts:46 suggests one might exist), strict mode fails. To confirm, inspect the Login page's accessible names.
- **start-bond.spec.ts:182-185**: `inputValue()` is called on the `-select` and `-state-select` test IDs. If these are custom div-based selects, `inputValue()` throws. To confirm, run TC-041 or inspect the element tag.
- **BondCreationPage.ts:173-176**: whichever promise loses the race (`validationBanner.waitFor()` or `waitForResponse`) keeps waiting and may reject at teardown. To confirm, look for unhandled-rejection errors in a TC-044 run.
- **security.spec.ts:84**: `PASSWORD` is passed as a `page.evaluate` argument, which the trace may record, as in #4. To confirm, open the trace of a retried SEC-006.
- **usability.spec.ts:59-76**: USA-009 compares computed styles right after focusing. A CSS focus transition could make it read the unfocused style and report a false failure. To confirm, run it with `--repeat-each=3`.

## What is done well
- Test IDs for form fields are mapped once and typed by `BondField` (src/pages/BondCreationPage.ts:13-30, :239-248; test-data/constants.ts:45-64).
- Text-based locators take their text from constants, and the one text fallback is documented (BondCreationPage.ts:233-234, :240-242).
- Missing configuration fails clearly and never skips: tests/ui/login/lockout.spec.ts:26-30, src/api/LoginApi.ts:8-16, src/utils/environment.ts:2-10, src/helpers/bondCreation.ts:34-35.
- Error messages name the missing variables but never print their values.
- SEC-006 returns only key names from the browser, never stored values (tests/non-functional/security.spec.ts:74-85).
- Specs that change state are placed and tagged with care. The logout specs sort last (tests/ui/logout/logout.spec.ts:3-4), SEC-001 uses its own session (tests/ui/logout/session-invalidation.spec.ts:5-7), and the lockout tests run serially on a separate account. The workflow also blocks a lockout account that is the same as the main account (.github/workflows/playwright.yml:37-40).
- TC-045 proves that Cancel sends no execute request by counting network requests (tests/ui/bond-creation/start-bond.spec.ts:246-254).
- `submitQuoteSuccessfully` fails fast with the app's own validation message (src/pages/BondCreationPage.ts:172-180).
- Failure screenshots come from one automatic fixture (src/fixtures/qa.ts:22-36).
